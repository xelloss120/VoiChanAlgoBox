# 遅延

## なぜ遅れるのか

リアルタイムのボイスチェンジャーで、話してから変換された声が聞こえるまでの遅れを**遅延**（レイテンシ）と呼びます。遅延が大きいと、自分の声が遅れて聞こえて、しゃべりにくくなります。

遅延の原因は、大きく 2 つあります。

1. **オーディオの入出力**: オーディオインターフェースとドライバが、ブロック（たとえば 128 サンプル = 約 2.7ms）ごとに音をやりとりする分。VoiChanAlgoBox の遅延の表示には含みません。
2. **処理そのもの**: 処理が、少し先の音を見ないと決められない分。方式によって大きく違います。

処理そのものの遅れは、主に次の理由で生まれます。

| 理由 | 例 |
|---|---|
| 窓の長さの分の音がたまるのを待つ | FFT の方式は、窓の長さの分（の一部）だけ遅れる（フェーズボコーダの窓 1024 で約 16ms） |
| 声の周期を知るのに、2 周期分の音が要る | ピッチ検出、TD-PSOLA（探す範囲の下限 80Hz で約 25ms） |
| 先を見てから決める | pYIN、RAPT、DIO、Harvest、リミッターの先読み 1ms |
| まとめて計算する | WORLD は 20ms ごとに、前後に余裕を持たせて分析する（約 84ms） |
| AI の処理単位 | RNNoise は 10ms ごとの処理と 1 回分の先読みで約 30ms |

## 遅延 0 の工夫

デノイズは、ボイチェンの遅延と足し合わされるので、できるだけ遅らせたくない段です。VoiChanAlgoBox では、「どれだけ下げるか」を決める分析は遅れて行い、実際に下げるのは今の音にかける、という工夫で遅延 0 にした方式を用意しています（[遅延 0 でかける工夫](../denoise/05-zero-latency.md)）。代わりに、急な変化（語頭）への反応が少し遅れます。

コンプ、ディエッサー、ゲートも、先読みをしない作りにして遅延 0 にしています。

## 画面の遅延の表示

画面の上には、遅延の合計と内訳（ボイチェン / リペア / デノイズ / 出力）を表示します。

- **計算値**: 方式の作り方から求めた遅れです。DAW には、この値を遅延として伝えます（DAW が遅延を補正するときに使います）。
- **実測**: 設定を変えると、裏で声に近いテスト音を処理して、入力と出力のずれを測った値です。ディレイライン式のように遅れが動く方式では、計算値と少し違います。

## 聞きどころ

- 方式を切り替えながら遅延の表示を見てください。周波数シフト（約 0ms）から WORLD（約 84ms）まで、大きく違います。
- 同じ方式でも、ピッチ検出の方式や探す範囲の下限、FFT の窓の長さを変えると、遅延が変わります。
- ヘッドフォンで自分の声を聞きながら話すと、遅延が 30ms を超えたあたりから、遅れが気になり始める人が多いと言われます。
